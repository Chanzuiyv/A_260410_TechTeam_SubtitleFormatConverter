# 🎧 团综字幕爬虫文本批量格式转换工具（逐声计划 · 技术组）

> 将猫耳 FM（missevan.com）两路爬虫抓取的自动字幕原始文本，批量清洗、去重、结构化，转换为统一的"规范剧本"格式，覆盖 7 张虚拟偶像团综专辑、共 **1186 个成稿文件**。纯 Python 标准库实现，零第三方依赖，开箱即用。
>
> 关键词：`Python` `文本清洗` `正则表达式` `批量文件处理` `目录树保持` `编码处理` `规则引擎`

---

## 一、项目背景 & 目标

"逐声计划"团综文字整理项目需要将音频节目的字幕整理为可阅读的剧本稿。原始字幕来自两套爬虫（组内两路数据来源："橘子爬虫"与"云攸爬虫"），存在三个问题：

1. **格式不统一**——两路爬虫输出的时间轴格式完全不同（普通时间轴 vs LRC 风格），且夹杂文件头元数据；
2. **噪音多**——自动字幕中混入字幕组署名、纯团名刷屏、单字感叹刷屏、同一名重复喊话等弹幕式垃圾行；
3. **不成剧本**——角色台词、环境描写、旁白混排，同一台词因抓取重复出现多次。

本项目的目标：编写批量转换脚本，**自动完成时间轴清洗 → 垃圾过滤 → 角色/环境/旁白结构化解析 → 台词去重 → 规范排版**，并严格保持原有的专辑目录结构，让上千个文件一键成稿、可直接交付校对。

> ℹ️ 本仓库为"格式转换"环节的交付：包含爬虫产出的原始数据、转换脚本、异常质检表与最终成稿。爬虫程序本身不在本仓库中；其数据来源可由 `异常报告.csv` 中的请求 URL（`https://www.missevan.com/sound/getdm?soundid=...` 猫耳 FM 弹幕接口）证实。

## 三、数据说明

### 1. 数据来源

猫耳 FM 虚拟偶像团体 LASER / MANTA 的团综、单曲、小剧场、福利音声等节目字幕，按 **7 张专辑**组织：

`FINE DAY`、`LASER出道日`、`NEW DAYS`、`WE FOUR`、`一起再出发`、`名利场`、`险象环声`

### 2. 两路原始数据格式对比

| 数据来源 | 文件数 | 时间轴样式 | 特征 |
|---|---|---|---|
| 橘子爬虫未格式化 | 1307 个 txt | `00:05:57.00 - 顾子尧：大家好` | `HH:MM:SS.ms - 文本`，无文件头 |
| 云攸爬虫未格式化 | 540 个 txt | `[09:56.34]柏闻：5个人就位了` | LRC 风格 `[MM:SS.ms]文本`，含 `[ver:v1.0]`、`[nickname:...]`、`[ti:标题]` 头信息 |

### 3. 异常报告（爬虫质检表）

每个橘子爬虫专辑目录下附 `异常报告.csv`（共 7 份），记录爬虫阶段的质检信息，字段包括：剧集文件名、soundid、请求 URL、剧集近似时长、弹幕总数、官方弹幕数、官方 ID 列表、异常原因（如"歌曲类_空文件待处理""无官方 ID"）、单人福利超 15 条、锁定角色无 ID，以及九位角色各自的关联弹幕 ID 数。该表用于人工判断哪些音频无官方字幕、需要重点校对。

## 四、处理流程

针对两路数据的格式差异，分别由两个脚本处理（规则一致，解析器各自适配）：

```
原始 txt
  │
  ├─ 步骤1  时间轴清洗：正则剥离行首时间戳（云攸版额外二次兜底，并删除所有含英文 [ ] 的元数据行）
  ├─ 步骤2  垃圾行过滤：命中规则即整行丢弃（见下方规则表）
  ├─ 步骤3  结构化解析：区分【环境描写】/ 角色：台词 / 普通旁白
  ├─ 步骤4  台词去重：重复内容只保留第一次出现
  └─ 步骤5  规范排版输出：按专辑原目录树写入同名 txt（UTF-8）
```

### 垃圾过滤规则（满足任一即丢弃该行）

| # | 规则 | 示例 |
|---|---|---|
| 1 | 含关键词：`字幕`、`字幕君`、`字幕组`、`野生`、`毒唯` | "感谢野生字幕君" |
| 2 | 清洗标点后仅为团名 LASER / MANTA（不区分大小写） | "LASER！！！" |
| 3 | 同一字符重复 ≥ 4 次的纯感叹刷屏 | "哈哈哈哈"、"啊啊啊啊" |
| 4 | 角色名/别名/团名在同一行出现 ≥ 3 次（云攸版为全部名字累计计数） | "乔殊乔殊乔殊！" |
| 5 | （仅云攸版）行内含英文方括号 `[` `]` | `[ver:v1.0]`、`[ti:标题]` |

角色别名表内置：季少、殊殊子、吱吱、顾饺、宁宁、安安、柏队、克制哥等。

### 结构化与排版规则

- **角色台词**（`角色名：台词`）→ 角色名单独占一行并加方括号，台词另起一行缩进 4 空格；非常驻角色同样处理；
- **环境描写**（`【内容】` 且内容不是角色名）→ 转为中文圆括号 **顶格**输出：`（内容）`；
- **普通文本/旁白**（无角色名的续句）→ 缩进 4 空格；
- **去重**：橘子版按台词文本全局去重（环境描写不参与去重）；云攸版按"类型 + 角色 + 内容"组合键去重，避免不同角色相同台词被误删。

### 角色体系

- 9 位常驻角色硬编码：顾子尧、夏予扬、乔殊、林致、柏闻、季少一、江恪、许向安、许向宁；
- 云攸版额外从爬虫产出的"剧集信息"CSV 的 `temporary_chars` 字段动态加载**非常驻角色**（如旁白、主持人、客串角色），用于正确区分"角色标记"与"环境描写"。

### 转换前后对比

转换前（橘子爬虫原始文本）：

```text
00:06:07.27 - 顾子尧：大家好，我们是——
00:06:18.89 - 顾子尧：很激动，也很荣幸
00:06:21.58 - 林致：是的，尤其是入围这个奖项
00:06:24.90 - 能和这么多优秀的同行站在一起
```

转换后（规范剧本）：

```text
【顾子尧】
    大家好，我们是——
【顾子尧】
    很激动，也很荣幸
【林致】
    是的，尤其是入围这个奖项
    能和这么多优秀的同行站在一起
```

## 五、运行方式

1. 打开脚本，将文件顶部的路径常量改成本机的输入/输出目录：

```python
# 格式转换.py（橘子爬虫版）
INPUT_FOLDER  = r"...\橘子爬虫未格式化"
OUTPUT_FOLDER = r"...\规范剧本_橘子"

# 格式转换云攸.py（云攸爬虫版，另需指定角色表目录）
INPUT_ROOT  = r"...\云攸爬虫未格式化"
OUTPUT_ROOT = r"...\规范剧本_云攸"
ROLES_DIR   = r"...\自动获取弹幕\剧集信息"
```

2. 直接运行：

```bash
python 代码/格式转换.py
python 代码/格式转换云攸.py
```

控制台逐文件打印 ✅/❌ 状态，结束时输出成功统计；输出目录不存在会自动创建，目录结构与输入保持一致。

> ⚠️ 注意事项：
> - 输入 txt 需为 **UTF-8 编码**；云攸版读取 CSV 使用 `utf-8-sig` 以兼容带 BOM 的文件；
> - 橘子版仅遍历**一级子文件夹**（不递归），云攸版使用 `os.walk` **递归遍历**整棵目录树——使用时请按实际目录层级选择脚本。

## 六、处理结果

| 阶段 | 橘子爬虫 | 云攸爬虫 | 合计 |
|---|---|---|---|
| 原始 txt | 1307 | 540 | 1847 |
| 成稿 txt | 642 | 544 | **1186** |
| 异常报告 CSV | 7 份（每专辑 1 份） | — | 7 |

- 成稿按 7 张专辑 × 两路来源完整组织，`最终结果/` 即交付版本（与 `test_output/` 经逐文件比对完全一致，互为备份）；
- 两路输入与成稿并非严格一一对应：`test_input/` 与 `test_output/` 是不同批次的快照，文件总数存在差异（如云攸路成稿 544 个、输入 540 个）。橘子路原始抓取中还包含歌曲、空文件等无需成稿的条目（异常报告中标注为"歌曲类_空文件待处理"），部分重复集数位于 `名利场/正剧/` 等嵌套子目录，而橘子版脚本只遍历一级子文件夹，因此该路成稿数明显少于原始文件数。

> 📌 技术要点小结：本项目的核心不是"读写文件"，而是为两套异构、高噪声的爬虫数据设计**可解释、可维护的规则引擎**——用正则做时间轴与行类型判定，用角色名单 + 别名表 + 垃圾关键词 + 频次阈值四层规则保证成稿质量，并通过动态加载非常驻角色表兼顾不同专辑的人物差异。
